Find and Replace Across Website Source Files

Changing one value in dozens of files by hand is slow and error-prone. A project-wide find and replace does it in one pass, if you do it carefully.

Typical jobs are changing an old domain to a new one, swapping an analytics ID, renaming a CSS class, fixing a broken link that appears on many pages, or removing a leftover test snippet.

Step by step in CodeShield

  1. Analyze your own public URL, or import your project as a ZIP in CodeShield.
  2. Open the Find & Replace workspace. It stays linked to the same project you just loaded.
  3. Search for the exact text. The results show every file and location where it appears.
  4. Check a few matches to confirm they are the ones you want to change.
  5. Use Replace All, or open a single file, edit it and choose Save File Changes.
  6. Export the updated project as a ZIP and upload it to your host.
Edits are localChanges affect the local project export only. They never modify the original live website until you deploy the exported files yourself.

Tips to avoid mistakes

  • Keep a copy of the original ZIP before replacing anything.
  • Search for a longer, specific string rather than a short word that appears everywhere.
  • Replace URLs including the protocol, for example https://old.example.com, so you do not damage similar text.
  • Review minified files separately; a replacement inside them is harder to verify.
  • Test the exported site locally before publishing.

Good uses after a security review

After a scan, use find and replace to remove a hard-coded key reference or point a call to your own server endpoint. Remember to rotate any real secret that was ever public; see the exposed API key guide.
